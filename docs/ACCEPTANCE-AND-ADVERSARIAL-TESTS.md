# 乐也教学管理系统 V1：需求对照与对抗式验收矩阵

本文以产品已确认规则为准。状态标记：
- **已实现（待端到端复验）**：代码中有对应逻辑，但尚不能据此认定真实环境通过。
- **部分实现**：只有 API 或基础页面，缺少完整业务操作体验。
- **未完成**：尚无可验收的完整流程。
- **禁止项**：不得重新引入。

## 7. 当前必须优先完成的阻断项

1. 管理员正式登录、角色/权限与审计操作者身份。
2. 管理后台继续从“手填 ID + JSON 输出”升级为可搜索、可选、可查看详情的日常教务工作台；本轮已增加每日课次列表、单个学员授课确认/消课、请假/缺勤、停课登记和监护人权限管理。
3. 调课、停课、考勤、成长记录编辑/发布、课时冲正更正的完整操作闭环。
4. 家长多监护人、多孩子和逐项权限的自动化集成测试。
5. 教室容量、排课冲突并发、重复消课、退款生命周期等数据库集成测试。
6. 微信真实登录、手机号验证、真机网络配置和订阅消息联调。
7. 生产部署、备份恢复演练；不得在未备份的生产数据库上试跑迁移。

## 8. 不可违反的产品规则

- 家长端只读查看，不自主预约、不在线购买、不在线支付、不线上请假、不预约补课。
- 续费、价格沟通、订单建立和线下收款由工作室负责人管理。
- 只有真实完成授课才可正常消课；时间经过不自动扣课时。
- 请假、缺勤、教师无法授课、工作室停课不自动扣课时。
- 赠送课时优先消耗；不允许负余额；更正必须留存完整流水。
- 旧预约数据保留，不删除旧表和历史记录；旧预约流程保持关闭。
- 工作室时区固定为 America/Chicago，数据库时间存 UTC。
- AI 不能绕过业务 API 直接修改数据库；高风险动作必须人工确认。
